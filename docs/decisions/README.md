# Architecture Decision Records

This directory contains Architecture Decision Records (ADRs) for the **Shoulder on FHIR** project.

## What is an ADR?

An ADR captures a significant architectural or design decision: the context that prompted it, the decision itself, the alternatives that were considered, and the consequences. ADRs are written once and then left in place — if a decision is later reversed, a new ADR is created and the old one is marked **Superseded**.

This project uses the [MADR](https://adr.github.io/madr/) (Markdown Architectural Decision Records) style, extended with a **Sources** section that traces each decision back to git commits, config files, or research documents.

## How to read an ADR

Each ADR has these sections:

| Section | Purpose |
|---------|---------|
| **Context** | Why was a decision needed? What constraints, requirements, or events drove it? |
| **Decision** | What was decided? |
| **Alternatives Considered** | What else was evaluated, and why was it not chosen? |
| **Consequences** | ✅ Benefits, ⚠️ trade-offs, ❌ drawbacks |
| **Sources** | Git commits, file paths, or research documents that evidence the decision |

**Sources naming `shoulder-surgeon`:** several records list a `shoulder-surgeon` subagent review under
their Sources heading. That is an AI review agent used to pre-check clinically sensitive modelling
before implementation, and it is not the human consulting shoulder surgeon who reviewed the running
demonstrator. Where a record cites the subagent, every terminology code it proposed was afterwards
verified against its authoritative server before being bound.

**Status values:**
- `Accepted` — decision is in effect
- `Accepted — rationale reconstructed` — the decision predates the ADR log; the rationale was reconstructed from the resulting configuration rather than recorded at the time
- `Superseded by ADR-XXXX` — this decision was later reversed; see the linked ADR

## How to add a new ADR

1. Copy `template.md` to a new file named `NNNN-short-title.md` (next sequential number).
2. Fill in all sections. Be specific: name the files changed, the commit that introduced the decision, or the error message that ruled out an alternative.
3. If the new ADR supersedes an existing one, update the old ADR's Status line to `Superseded by ADR-NNNN`.
4. Add an entry to the index below.
