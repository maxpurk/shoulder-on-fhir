## Terminology provenance at a glance — two axes

Every consensus element is representable in the IG, and none is unmodellable in FHIR (**0 Missing**). Beyond that, the mapping records **terminology provenance** per element, split across the two FHIR bindings that carry clinical meaning, and orthogonal to the `Consensus` / `IG-Operational` **layer** axis:

- **Code Provenance** (identity — `Observation.code` / `Condition.code`): `Reused` (an external concept code: SNOMED CT / LOINC / DICOM / HL7 / ICD), `Local` (this IG's own published CodeSystem), or `—` (no concept code; a structural FHIR element).
- **Value Provenance** (result — `value[x]`): `Reused`, `Local`, `Numeric` (a UCUM magnitude carrying no concept vocabulary), or `—`.

Provenance is judged by the **code system on the wire**, not by who authored the ValueSet: a locally-authored ValueSet that enumerates only external codes (e.g. `PositiveNegative` → SNOMED `10828004`/`260385009`) is `Reused`. An element whose sub-measurements differ within one facet carries both, written `Reused + Local` or `Numeric + Local`. Binding strength is a further nuance recorded in the CSV `Binding Strength` column (a `Local` code under a `required` binding is a harder interoperability constraint than under `extensible`).

The **terminology frontier** — the concepts standard code systems do not yet carry, and so the exact upstream-submission worklist — is every element with a `Local` cell in either facet.

| Layer | Elements | Code: Reused / Local / mixed / — | Value: Reused / Local / Numeric / mixed / — | Frontier (any Local) |
|---|---|---|---|---|
| **Consensus** (Layer 1) | 58 | 16 / 27 / 9 / 6 | 18 / 7 / 9 / 10 / 14 | **38** |
| **IG-Operational** (Layer 2) | 43 | 4 / 5 / 0 / 34 | 12 / 5 / 0 / 0 / 26 | 7 |

(Value "mixed" for the consensus layer = `Reused + Local` (2) + `Numeric + Local` (8) = 10.)

**Reading (Consensus layer): 20 of 58 elements are carried entirely by reused external terminology; the other 38 draw on at least one project-defined code.** The residual barrier is terminology, not structure: every element is modellable in FHIR, but many shoulder-specific concepts have no standard code and resolve locally (see the frontier list below).

The IG carries no convenience PROMs beyond the consensus — ASES, WORC, DASH and QuickDASH are absent because none passed the 80% Delphi threshold, and carrying them would be inconsistent with the consensus-only discipline. There is likewise no lost-to-follow-up tracking pattern: the consensus never asks for one, the IG does not declare one, and no profile or frontend realises one. See ADR-0054 and ADR-0180.

## Terminology frontier — the project-defined concepts (submission worklist)

Every consensus element is representable; Q7 (ultrasound, 60% agreement — below the 80% Delphi threshold) is excluded from the consensus denominator and relocated to Layer 2. The 38 frontier elements resolve to these distinct project-defined concepts, the candidates for upstream submission to SNOMED CT / LOINC:

- **Provocation tests** with no SNOMED CT test-procedure concept: belly-press, bear-hug, Hornblower (Q2.g–i, Q9.g) — `Local` code, `Reused` (SNOMED) positive/negative value
- **Pain** — four context-specific 0–10 axes (Q1.h, Q8.a, Q12.a): `Local` code, `Numeric` value
- **Strength** — MMT ordinal + supraspinatus dynamometry (Q2.d, Q9.d, Q12.b, Q8.c): `Local` code, `Numeric` value
- **Internal-rotation vertebral ladder** and the two 90°-abduction rotation axes (within Q2.b/c, Q9.b/c): `Local`
- **Inspection** — atrophy and normal-contour codes (Q2.a, Q9.a): `Local` code (deformity is SNOMED; value is SNOMED present/absent)
- **Tear classification** — Cofield tear-size bucket + linear cm (Q4.a), tendons-involved code (Q4.b), tear-thickness code (Q4.c), Patte (Q4.d), Goutallier (Q4.e)
- **History / social ordinals** — sleep disturbance (Q1.i), sports level (Q1.j), occupational physical-demand + overhead exposure (Q1.k), functional-limitation ladder (Q1.n, Q12.c)
- **Outcome** — return-to-sport/work (Q12.e), SSV/SANE (`Numeric` value), the four Constant-Murley sub-scores (Q12-Constant, `Local` component values)
- **Local supplements to otherwise-standard value sets** — acute-on-chronic etiology (Q1.e), self-employed (Q1.k employment)
- **Research schedule** — the local `Q11Timepoint` discriminator (Q11.a–e)

The 20 fully-standard consensus elements (no `Local` in either facet) are the demographics (Q1.a–b), comorbidity codes (Q1.c), smoking (Q1.d), prior treatment (Q1.f), workers' compensation (Q1.l), hand dominance (Q1.m), the Jobe and lift-off tests (Q2.e–f, Q9.e–f), the imaging modalities (Q3, Q5, Q6), quality of life (Q8.d), satisfaction (Q8.e, Q12.g), the follow-up schedule (Q10, Q13), and impact on daily activities (Q12.f). Seventeen carry reused SNOMED CT / LOINC / DICOM / HL7 terminology in every facet they populate; the remaining three (Q1.a age, Q8.d, Q12.f) are `Local`-free because they have no coded facet to be local in.

## Interpretation notes

Some consensus elements are single-word terms that the IG must operationalise as a specific FHIR shape. These are decomposition choices made by this IG, not the consensus's own wording — flagged here for transparency:

- **Q1.b "Gender"** → implemented as FHIR base `Patient.gender` (1..1 MS, required-bound to `administrative-gender` — male / female / other / unknown). The IG additionally adopts HL7 Gender Harmony's `individual-recordedSexOrGender` (RSG) extension as `ShoulderPatient.extension[recordedSexOrGender] 0..1 MS` (tracked at `L3.A.6`) to carry sex assigned at birth as a separate research-stratification variable. `type` is pinned to LOINC 76689-9 so every RSG instance uniformly represents sex at birth; `value` is `required`-bound to `administrative-gender`. R4-backported via `hl7.fhir.uv.extensions.r4`. The EU Base SFCU extension is not used: it is a runtime CDS directive, not a demographic. The German `gender-other-de` extension is deferred to deployment-time customisation. See ADR-0053.
- **Q1.c "Comorbidities"** → implemented as a dedicated `ShoulderComorbidityCondition` profile (parent: base `Condition`), with `Condition.code` `extensible`-bound to the IPS 1.1.0 problem-list ValueSet `http://hl7.org/fhir/uv/ips/ValueSet/problems-snomed-absent-unknown-uv-ips` (composes SNOMED ECL `< 404684003 |Clinical finding|` + `< 243796009 |Situation|` + `< 272379006 |Event|`, excluding `< 71388002 |Procedure|`). The IG tightens IPS's `preferred` to `extensible` because a new single-jurisdiction registry's value proposition is structured comparability — `preferred` would produce no validator pushback if a clinician records a comorbidity in plain ICD-10-GM with no SNOMED, undermining the structured comparability the registry depends on. Under FHIR R4 semantics, `extensible` is satisfied when at least one `coding[]` entry is from the bound VS, so ICD-10-GM and other codings remain permitted as additional siblings (dual-coding) at deployment time without a structural change. `category` is fixed to `problem-list-item` — distinct from `RotatorCuffCondition`'s `encounter-diagnosis`. Carried on the new `RotatorCuffRegistrationBundle.entry[comorbidity] 0..*` slice. The frontend (port 3000) ships a SNOMED typeahead bound to this VS, debounced over `$expand?filter=…` against `tx.fhir.org` per ADR-0050. Stock SDC cannot typeahead a SNOMED ECL VS out of the box (no built-in `#open-choice` search renderer), so the SDC frontend adds an `#open-choice` item type plus a `SnomedTypeahead`/`useSnomedTypeahead` capability (`searchValueSet`/`expandFiltered`, same exclusion set) (ADR-0137). See ADR-0055.
- **Q1.e "Traumatic etiology"** → implemented as a post-coordinated CodeableConcept on `Condition.extension[condition-dueTo]` (FHIR R4 standard cause extension), bound `required` to `RotatorCuffEtiology` (4 codes: traumatic / degenerative / mixed / unknown). The expert consensus names a binary axis; the IG decomposition adds "mixed (acute-on-chronic)" because the case is clinically common, and "unknown" because the registry must accept missing data without omitting the field. Carrying etiology on its own element rather than pre-coordinating it into `Condition.code` keeps Q1.e's etiology a coded value (`Reused` SNOMED, with the local acute-on-chronic supplement) regardless of which anatomic-pathologic code the clinician picks. `onset[x]` is temporal metadata and carries no part of the etiology. See ADR-0046.
- **Q1.h "Pain"** (also `Q8.a` "improved pain" and `Q12.a` PROM pain component, which share the same profile family) → implemented as four context-specific 0–10 numeric-rating measurements — on average, with active movement, with passive movement, at rest — each a dedicated Observation profile (`PainAverageObservation`/`PainActiveMovementObservation`/`PainPassiveMovementObservation`/`PainRestObservation`) with a local `ShoulderObservationCodes` code. The expert consensus names only "Pain"; the four-item decomposition mirrors this IG's own active/passive split, already used throughout its ROM profiles. No precoordinated LOINC or SNOMED CT concept exists for any of the four pain-context axes (verified July 2026); generic LOINC `72514-3` carries no context qualifier, so it is not used for any of the four — it would leave ambiguous which context a value represents. All four are reused symmetrically across `Q1.h`/`Q8.a`/`Q12.a`, differentiated by `effectiveDateTime`. See ADR-0087.
- **Q1.i "Sleep disturbance"** → implemented as a 3-tier ordinal (unaffected / occasionally disturbed / nightly disturbed), `valueCodeableConcept` bound `required` to a new local `SleepDisturbanceSeverity` ValueSet, matching the Constant-Murley score's own ADL sleep sub-item (the expert consensus Q12 preferred outcome instrument) rather than inventing a new scale. The expert consensus names only "Sleep disturbance" with no mechanism specified. The item asks specifically about shoulder-caused disturbance and is wired into `RotatorCuffCondition.evidence.detail` (the same mechanism as the provocation tests), so the attribution is a queryable FHIR relationship rather than something implied by question wording. No SNOMED CT or LOINC concept exists for this axis (verified July 2026). See ADR-0081.
- **Q1.j "Sports"** → implemented as a 4-tier participation-level ordinal (none / recreational / competitive / professional), `valueCodeableConcept` bound `required` to a new local `SportsParticipationLevel` ValueSet, with local code `ShoulderObservationCodes#sports-participation` retained on `Observation.code`. The expert consensus names only "Sports"; the term could equally be read as binary participation (yes/no). The IG reads it as a coded ordinal — strictly more informative than the binary reading (the `none` grade subsumes it) and comparable across patients, coarsely aligned with DART's `DEM-08` "Activity level (pre-injury)" enum and the Tegner Activity Scale without importing Tegner's lower-limb-specific item descriptors. No SNOMED CT or LOINC ordinal value codes exist for this axis (verified July 2026; SNOMED `social_context` has no match for "sports participation"/"competitive sport", `observable_entity` has candidate axis codes but no precoordinated grade values, LOINC's `LL6103-7` answer list has no bindable FHIR ValueSet). See ADR-0083.
- **Q1.k "Occupation"** → implemented as three coded axes rather than a free-text job title: employment status (`valueCodeableConcept`, LOINC `67875-5` fixed `code`, bound `required` to a hybrid ValueSet — LOINC's own official `LL1901-9` answer list plus one local "self-employed" addition that list is missing); occupational physical-demand intensity (`valueCodeableConcept`, fully local `code` and `ValueSet` — sedentary / light manual / heavy manual — no SNOMED/LOINC concept exists for this axis, verified July 2026); and occupational overhead-work exposure (`valueCodeableConcept`, fully local, yes/no/unknown), an axis independent of physical demand, so an occupation that is simultaneously heavy AND overhead (e.g. a roofer) is not forced into an either/or choice. The expert consensus names only "Occupation" with no mechanism specified; a free-text job title (LOINC `85658-3`) carries little analytical value and is not used. Both physical-demand axes are IG decomposition choices motivated by overhead/repetitive shoulder loading being a well-established rotator-cuff risk and return-to-work factor — not captured by any comparable registry surveyed (DART, EPRD, IRD, SEPR). See ADR-0082 and ADR-0105.
- **Q1.n "Functional limitations"** → implemented as a five-tier functional-ceiling ordinal (no limitation / overhead-limited / at-shoulder-level-limited / below-shoulder-limited / unable to use the arm), `valueCodeableConcept` bound `required` to a new local `FunctionalLimitationSeverity` ValueSet. The expert consensus names only "Functional limitations" with no mechanism specified. A coded ordinal is analyzable across the registry where a `valueString` free text is not — the same reasoning that governs Q1.i sleep disturbance (ADR-0081) and Q1.j sports participation (ADR-0083). Each tier is a strict functional subset of the one above, deliberately distinct from the Constant-Murley score's own ADL sub-component (`component[ADL]`, already implemented, ADR-0090) — this is a one-item baseline gestalt, not a duplicate instrument. No SNOMED CT or LOINC concept exists for this axis (verified July 2026). See ADR-0105.
- **Q4.c "Partial vs full thickness"** → decoupled from `Condition.code` onto its own `TearThicknessObservation`, `valueCodeableConcept` bound `required` to a new local `TearThickness` ValueSet reusing two precoordinated SNOMED CT concepts (`202843000` full-thickness / `202842005` partial-thickness) as Observation values. Keeping thickness off `Condition.code` prevents disease-entity choice from being entangled with it, mirroring the "one axis, one element" principle already applied to tendon involvement (Q4.b, ADR-0064) and etiology (Q1.e, ADR-0046). Linked to the index `RotatorCuffCondition` via `Condition.evidence.detail`. See ADR-0106.
- **Condition→Observation linkage (stage vs evidence)** → the imaging-derived classification Observations attach to the `RotatorCuffCondition` through two ADR-0073 buckets, not one. Formal **gradings** — Patte (Q4.d), Goutallier (Q4.e), and the Cofield tear-size bucket (Q4.a) — link via `Condition.stage.assessment` (they presuppose the diagnosis and grade its severity). **Diagnostic evidence** — tendons involved (Q4.b), tear location, tear thickness (Q4.c), and the provocation tests — links via `Condition.evidence.detail`. The raw continuous tear-size measurement (cm) is in neither bucket, reachable only through the encounter chain. Both frontends and the seed data implement this split. See ADR-0073.
- **Q2.a / Q9.a "Inspection"** → implemented as three structured present/absent findings (Atrophy, Deformity, Normal Shoulder Contour), each a dedicated Observation profile with `valueCodeableConcept` bound `required` to a new local `PresentAbsent` ValueSet (standard SNOMED CT qualifiers `52101004` Present / `2667000` Absent). The expert consensus names only "Inspection" with no mechanism specified for either the pre-treatment (Q2.a) or post-treatment (Q9.a) exam. A free-text `valueString` is not analyzable across the registry, so the three findings carry coded values; they are shared across Q2.a/Q9.a via `effectiveDateTime`. The SNOMED CT disorder/finding hierarchy carries laterality-neutral concepts for two of the three axes — Atrophy (`1119438000` "Atrophy of muscle of shoulder") and Deformity (`111263009` "Acquired deformity of shoulder"). Deformity uses `111263009` as `Observation.code`, paired with the same standard SNOMED present/absent value axis. Atrophy keeps a local code: `1119438000` is a real, current concept but does not resolve against `tx.fhir.org`'s served SNOMED CT International Edition snapshot, which breaks both submission-time client validation and `tools/validate.sh`; it is a candidate for migration once that served edition carries the concept. Normal Shoulder Contour has no equivalent concept and keeps its local code. See ADR-0086, ADR-0115, ADR-0116.
- **Q2.b/Q2.c "Active/Passive ROM"** (also `Q9.b`/`Q9.c`, the post-treatment counterparts sharing the same profile family) → six measurement axes, not four. The expert consensus names only "Active/Passive ROM" with no mechanism, plane, or measurement position specified. Flexion, Abduction, and at-side External Rotation stay `valueQuantity` degrees on their existing LOINC codes (`41389-8`/`41381-5`/`41387-2` active, `41390-6`/`41382-3`/`41388-0` passive). At-side Internal Rotation is a local `valueCodeableConcept` bound `required` to an 8-tier `InternalRotationVertebralLevel` ordinal — the standard "hand behind back" functional reach scale (unable / greater-trochanter / buttock / sacrum / L5 / L3 / T12 / T7-or-above) — rather than a degree measurement, because goniometric IR degrees are clinically unreliable at this position (scapulothoracic substitution confounds the angle). The ordinal reuses most of the Constant-Murley score's own IR landmarks and adds finer rungs, so the derivation of the Constant ROM sub-score applies a documented lossy remapping in which `l3` and `t12` collapse to the same point value (the expert consensus preferred PROM instrument, already modeled in this IG). Two local `valueQuantity` degree axes — External and Internal Rotation measured at 90° abduction, a controlled goniometer-reliable position distinct from at-side — assess capsular tightness (GIRD) and rotator-cuff competence that at-side measurement alone cannot quantify; both are out-of-consensus enrichments. All six rotation-degree profiles — at-side External Rotation plus External and Internal Rotation at 90° abduction, in both the active and the passive family — carry a `0–360°` bound: permissive for data entry, not a claim that 360° is an achievable physiological range. Flexion and Abduction stay bounded at `180°`. No LOINC or SNOMED CT code exists for a vertebral-level IR scale or for a position-specific ("at 90° abduction") rotation measurement (verified July 2026). See ADR-0045 and ADR-0088.
- **Q2.d "Strength (rotator cuff muscles)"** (also `Q9.d` and `Q12.b`, sharing the same profile family) → five measurement axes, not three. The expert consensus names only "Strength of the different muscles of the rotator cuff" with no mechanism specified. Supraspinatus (Jobe/empty-can), external-rotation composite (infraspinatus + teres minor), and subscapularis (lift-off/belly-press isolation) stay `valueQuantity` `{score}` 0–5 manual muscle testing grades, labeled as Janda grading (equivalent to MRC/Daniels-Worthingham — the same six 0–5 anchors; no SNOMED concept named "Janda" exists, only the generic observable entity `249956007` "MRC grade - muscle power", not bound). `InternalRotationStrengthObservation` (`valueQuantity` `{score}` 0–5) is the structural mirror of the external-rotation composite profile (tested at 0° abduction, elbow flexed 90°, resisted internal rotation) — clinically distinct from subscapularis isolation testing (which deliberately unloads the secondary internal rotators via a different position), so both are kept as independent sibling axes rather than treating one as redundant. `SupraspinatusStrengthDynamometryObservation` (`valueQuantity` kg) is a dual-encoding sibling of the ordinal grade, not a replacement for it, because ordinal grading is insensitive to partial supraspinatus weakness at grades 4–5 — mirroring the Q4.a tear-size cm/Cofield-bucket pattern. No shoulder-specific MMT LOINC exists; no LOINC/SNOMED concept exists for shoulder dynamometry or a "Janda" grading eponym (verified July 2026). See ADR-0089.
- **Q2.e/Q2.f/Q2.g/Q2.h/Q2.i "Provocation tests"** (Jobe / Lift-off / Belly-press / Bear-hug / Hornblower; `Q9.e`/`Q9.f`/`Q9.g` are the post-treatment counterparts the consensus re-asks) → all modeled uniformly as a dedicated Observation profile with `valueCodeableConcept` bound `required` to the shared local `PositiveNegative` ValueSet. Jobe (Q2.e/Q9.e) and Lift-off (Q2.f/Q9.f) carry verified SNOMED CT procedure concepts on `Observation.code` — `1231437004` "Empty can test" and `1231510004` "Lift-off test" (ADR-0115). The remaining three keep their local `ShoulderObservationCodes` codes (`#belly-press-test`, `#bear-hug-test`, `#hornblower-test`); a full SNOMED CT check via the FHIR terminology server (Aug 2026) found that belly-press and bear-hug have no SNOMED concept of any kind (zero description matches across every domain, although sibling shoulder tests Jobe/Lift-off/O'Brien/Yocum/Hawkins-Kennedy are published), and Hornblower exists only as the finding "Hornblower sign" (`1231519003`), not a test procedure — binding that finding as `Observation.code` and then pairing it with a "negative" value would be self-contradictory, so the local code is retained to keep all five tests on one positive/negative value pattern. These three are therefore `Local` on `Observation.code` while their positive/negative value is `Reused` (SNOMED), as for Jobe and lift-off; migrating the code to SNOMED is deferred to future work (`docs/future_work_items/`) pending publication of belly-press / bear-hug / Hornblower-*test* procedure concepts.
- **Q12-Constant "Constant-Murley score"** → `ConstantScoreObservation` carries `Observation.component[]` for the four sub-scores (Pain 0–15 / ADL 0–20 / ROM 0–40 / Strength 0–25, the original Constant & Murley 1987 breakdown), so they are retained rather than discarded after computing the total. Two entry modes on the same `valueQuantity` total field, distinguished by whether `component[]` is populated: direct total entry (no components — a legitimate registry pattern when only a prior report's published total is on hand) or component-derived entry (all four components present, `valueQuantity` = their sum, auto-calculated live in both frontends and via the SDC Questionnaire's `calculatedExpression`). Four of the eleven worksheet sub-items are auto-derived from this IG's own Observations by the shared sub-item calculator (Sleep, Flexion, Abduction, and the Internal Rotation ladder), using a banded conversion rather than a linear one, and the Internal Rotation remapping is lossy: `l3` and `t12` collapse to the same point value, as do `unable` and `greater-trochanter` (ADR-0112). The remaining sub-items are entered directly, because their existing IG counterparts measure a different construct: the Strength sub-score is a single spring-balance point value distinct from `SupraspinatusStrengthDynamometryObservation` (ADR-0089). No LOINC or SNOMED CT code exists for any of the four sub-components (verified July 2026) — local codes are fixed on the component slices; the total's `Observation.code` is SNOMED#273383002. `Observation.component` is used only here in this IG. Because `component[ADL]` is the only home the IG gives consensus element `Q12.f` (impact on daily activities), a direct-total submission carries no representation of `Q12.f` at that visit: the element is representable, but whether it is actually present depends on the entry mode chosen — a representability/completeness distinction, not a gap in the model. See ADR-0090.
- **Q4.a "Size"** → implemented as dual encoding: (i) continuous linear `valueQuantity` in cm and (ii) categorical Cofield bucket `valueCodeableConcept` (bound to `CofieldTearSizeClassification` — small <1 cm / medium 1–3 cm / large 3–5 cm / massive >5 cm). Both anchored on the same Encounter; the categorical bucket is computable from the linear measurement but captured at the source so downstream consumers do not need to re-bucket, and the IG aligns with the dominant convention in the shoulder literature. Each of the two encodings further splits into an imaging-context and a surgical-context sibling profile, differing only in a fixed `Observation.category` — `tear-size-observation`/`tear-size-classification-observation` (`category = imaging`, pre-op MRI/ultrasound, Registration bundle) vs. `intraop-tear-size-observation`/`intraop-tear-size-classification-observation` (`category = exam`, direct intra-operative measurement, Surgery bundle). Both are routinely recorded for the same patient by different means at different times, and disagreement between the pre-op estimate and the intra-operative measurement is clinically expected and meaningful — the split lets both coexist as distinct, non-redundant Observations rather than one silently overwriting the other. Q4.a is `Local` on both facets: no LOINC for maximum tear diameter and no SNOMED CT precoordinated concepts for the Cofield buckets exist (verified May 2026), so the linear-cm value is `Numeric` under a `Local` code and the bucket is `Local`/`Local`. See ADR-0047 and ADR-0104.
